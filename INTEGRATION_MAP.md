# Synth Integration Map

This is the Phase 0 plan-review artifact. Every product capability is initiated or administered through one of two roots: the project `synth` extension or the overlay `synth` CLI. Permitted vendored core patches execute inside Prime Agent, and promoted skill packages are discovered and executed by the existing skill/kernel runtime; both are subordinate native surfaces, not additional Synth product entry points. Setup, validation, and demo scripts are nonruntime drivers. The Phase 2 orphan checker must model these explicit surfaces rather than silently excluding them.

## Planned vendored-tree changes

Only Appendix A is planned: A1-A6 and changelog fragments in Phase 1, root documentation/ignore changes, and the bounded AutoSaddler copy in Phase 6. Extension, bridge, memory, BATS, optimizer adapters, and compiler logic remain outside `packages/**` and `prime-agent-runtime/**`. Any newly discovered core limitation stops implementation until `DECISIONS.md` records why the extension API is insufficient.

## Known plan-review questions resolved by recon

- Memory retrieval keys on `before_agent_start.prompt`; `session_start` only establishes lifecycle state.
- Native usage is read from assistant messages, not provider-response hooks.
- Project `models.json` is a shipped template and setup source, not an auto-discovered registry file.
- The kernel venv stays separate from the overlay venv so promoted skills remain provisionable.
- Exact telemetry transcript pointers are correlated after append; no hook-supplied ID is assumed.
- Dynamic Skill Compiler creates standard packages; it does not equate native HarnessState skill descriptions with installed skills.
